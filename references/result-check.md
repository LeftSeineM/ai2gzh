# 发布结果检查

为本次操作保留轻量记录（存用户工作目录，不提交公开仓库）：标题、目标账号的本地别名、提交时间、状态，以及取得的正式文章链接。内容和封面指纹可用于分辨重试与新版本。

| 状态 | 判定与下一步 |
| --- | --- |
| 草稿已保存 | 仅有草稿 ID 或草稿箱记录；尚未发表 |
| 等待验证 | 微信要求扫码/管理员确认；让用户处理 |
| 已提交或审核中 | 接受请求但没有最终结果；继续查询，不能再次提交 |
| 结果不明 | 连接断开、超时或浏览器退出；按标题和提交时间查发表记录 |
| 发表失败 | 展示微信具体失败原因；保留已建草稿，不自动重发 |
| 已发表 | 本篇文章在发表记录中确认成功，且取得正式文章链接 |

## 网页后台

在发表记录中按本篇标题及提交时间定位。页面上出现其他文章的“已发表”不能证明本篇成功。取本篇记录关联的 `https://mp.weixin.qq.com/s/...` 或 `https://mp.weixin.qq.com/s?...` 链接，不返回 `javascript:`、后台管理 URL 或带临时预览凭据的链接。

尽可能用没有公众号管理登录态的浏览器打开链接，核对文章标题和正文。单独 HTTP 200 可能只是验证码、验证页或加载壳，不足以证明读者能看到文章。若微信拦截自动化读取，明确区分“后台已发表并取得链接”和“匿名访问已验证”，不虚构验证结果。

## 官方接口（仅适用于已确认权限的接入）

创建草稿 → 提交 `freepublish/submit` → 保存 `publish_id` → 查询 `freepublish/get` → 成功状态和文章链接。提交任务成功不等于文章已上线。

遇到权限错误回到账号能力检查，不猜测个人订阅号具有某个接口权限，不把网页登录 Cookie 拼成未经验证的发文接口。

## 防止重复发表

提交前保存操作标识；已提交后只查询这次操作。对超时、崩溃、重启后的任务先查公众号后台。同一标题可能有多篇文章，结合提交时间和正文版本核实。除非确认未发表或用户明确要再发，不再次点击最终发表。
